# API каталога и свободных окон

Этап 1 платформы записи. Оба маршрута используют один каталог Laravel и доступны по Bearer-ключу. `CatalogService` и `AvailabilityService` можно вызывать из будущих адаптеров с их собственным набором разрешённых филиалов.

## Запуск в Postman

1. Из корня проекта выполните `bash scripts/booking-postman.sh`. Нужны установленные Composer-зависимости и расширение PHP SQLite. Скрипт запустит Laravel на `127.0.0.1:8011`, создаст отдельную SQLite-базу с вымышленными записями и напечатает путь к приватному окружению Postman. Для другого порта передайте его первым аргументом.
2. Импортируйте [коллекцию Postman](postman/booking-integrations.postman_collection.json) и сгенерированный файл `booking.postman_environment.json`. Выберите окружение **Laravel Booking · local demo**. В нём есть отдельный ключ Postman с правами `catalog:read`, `availability:read` и второй ключ только с `catalog:read` для проверки отказа.
3. Запустите всю коллекцию через Collection Runner. Запросы проверяют код ответа, ID и контрольные значения. Для запуска из терминала используйте `npx --yes newman run docs/postman/booking-integrations.postman_collection.json -e /путь/к/booking.postman_environment.json`.
4. Используйте окружение в день запуска демо по Москве. Для нового дня запустите скрипт снова и импортируйте новое окружение. Сервер останавливается по Ctrl+C. Файлы базы и окружения лежат в напечатанном временном каталоге.

В коллекции заголовки и авторизация заданы заранее. Для ручного запроса передайте `Accept: application/json`, `Authorization: Bearer <ключ>` и для POST `Content-Type: application/json`.

## Каталог

`GET /api/integrations/v1/catalog/search` с правом `catalog:read`.

- `type` и `q` обязательны. Поддерживаются `doctor`, `branch`, `city`, `clinic`. Для врача ищем по фамилии, ФИО или специальности. Для филиала ищем по названию или адресу.
- `city_id` сужает поиск. `limit` по умолчанию равен 20, максимум 50.
- Поиск учитывает регистр, пунктуацию и `ё/е` через нормализацию. Для фамилий на `-ая` поддерживаются формы на `-ой` и `-ую`.
- Если обычный поиск ничего не нашёл, каталог ищет похожие ФИО и названия филиалов, городов и клиник в пределах доступных филиалов. Для запросов от пяти символов допускается одна правка, от восьми — две. Если найдены похожие варианты, ответ содержит `meta.approximate: true`. В голосовом диалоге при таком ответе попросите пользователя подтвердить выбор перед поиском окон, даже если вариант один.
- `meta.ambiguous: true` означает, что совпадений несколько. Уточните выбор по имени, городу или адресу. `meta.has_more` показывает, что кандидатов больше лимита.
- Примеры для вкладки **Params**: `type=doctor&q=Видлацкой` возвращает двух врачей с ID `1` и `2`, адресами филиалов в Кирове и Москве. `type=doctor&q=офтальмолог&city_id=1` возвращает ID `1, 3, 6`. `type=branch&q=Ленина 1` возвращает филиал `1`, `type=branch&q=Север` — филиал `2`.

Специальность берётся из `doctors.specialty`. Для филиала 1С при пустом поле используется последняя по ID ячейка этого врача и филиала с заполненным `doctor.espec` или `doctor_speciality`. На этапе 1 фильтр `specialty` принимает текстовое название, например `офтальмолог` совпадает с `Детский офтальмолог`. Для локальных врачей заполните поле каталога при подготовке рабочего справочника.

## Свободные окна

`POST /api/integrations/v1/availability/search` с правом `availability:read`. Тело — JSON-объект.

| Поле | Поведение |
| --- | --- |
| `city_id` | Один город |
| `clinic_ids`, `branch_ids`, `doctor_ids` | Непустые списки ID. До 20 клиник, 20 филиалов, 50 врачей |
| `specialty` | Текст специальности, полученный из каталога |
| `date_from`, `date_to` | `YYYY-MM-DD`, обе даты включительно, до 31 дня. Только `date_from` выбирает один день. Без дат ищем сегодня по часовому поясу каждого филиала |
| `time_from`, `time_to` | `HH:mm`, включительные границы начала приёма на каждый день. Можно передать любую из них отдельно |
| `patient_age`, `birth_date` | Одно из двух полей. Возраст в полных годах от 0 до 130 либо дата рождения `YYYY-MM-DD` для расчёта возраста на дату приёма |
| `limit` | От 1 до 50 окон, по умолчанию 20. `meta.has_more` показывает, что лимит обрезал выдачу |

Значения внутри списка объединяются по ИЛИ, разные фильтры — по И. Пустые списки, лишние поля, несовместимые границы и явно указанные филиалы вне выбранной клиники, города или прав клиента дают `422`.

Филиал использует свой эффективный режим расписания с наследованием от клиники. Для локального режима используются смены, длительность слота филиала и занятость в заявках. Для 1С используются статусы ячеек, время последнего обновления и локальная занятость. Ответ содержит только подходящие будущие окна активных врачей в филиалах, к которым они привязаны. Сортировка идёт от ближайшего начала, затем по ID филиала, врача и окна. Время возвращается в ISO 8601 со смещением и IANA-зоной филиала. По умолчанию оба города используют `Europe/Moscow` из настроек приложения.

| HTTP | Что получает клиент |
| --- | --- |
| `200` | `data` и `meta.schedule_status` со значением `complete` либо `partial`. В `unverified_branches` указаны филиалы и даты с непроверенными данными |
| `401` | `code: unauthenticated` при отсутствующем или неверном Bearer-ключе |
| `403` | `code: insufficient_scope`, если ключ действителен, но отсутствует право на операцию |
| `422` | Ошибки фильтров в `errors` |
| `429` | Превышен лимит запросов с IP |
| `503` | `data: []`, `meta.schedule_status: schedule_unavailable`, если для подходящих филиалов и дат нет проверяемого расписания |

Для 1С порог свежести по умолчанию составляет 1440 минут. `BOOKING_ONEC_MAX_AGE_MINUTES` задаёт общий порог, `BOOKING_ONEC_MAX_AGE_BY_BRANCH` принимает JSON вида `{"12":120}` для настройки конкретных филиалов. День врача с устаревшими ячейками или без ячеек отмечается непроверенным. `complete` означает, что локальное расписание и доступные признаки свежести ячеек покрывают запрос. Текущая проекция 1С хранит время обновления отдельных ячеек. Подтверждение полного снимка со стороны 1С и различение выходного дня и пропуска выгрузки требуют явной информации о покрытии. При `partial` или `schedule_unavailable` сообщите, что часть расписания не удалось проверить.

## Проверочные запросы

Для примеров ниже день запуска — 10 ноября 2026 года. Коллекция автоматически подставляет даты из сгенерированного окружения.

### К Видлацкой сегодня или завтра, иначе ближайшее у неё

В каталоге `type=doctor&q=Видлацкой` найдите обоих кандидатов. После уточнения в демо выберите Видлацкую Анну, ID `1`.

1. `POST /api/integrations/v1/availability/search`

   ```json
   {"doctor_ids":[1],"date_from":"2026-11-10","date_to":"2026-11-11","limit":5}
   ```

   Ожидается `200`, `data: []`, `meta.schedule_status: complete`. Подходящие по датам окна заняты или прошли.

2. `POST /api/integrations/v1/availability/search`

   ```json
   {"doctor_ids":[1],"date_from":"2026-11-12","date_to":"2026-12-11","limit":1}
   ```

   Ожидается `200`, одно ближайшее окно у Анны и `meta.has_more: true`. Если пациент уже выбрал филиал, передайте тот же `branch_ids` в обоих запросах. Фрагмент `data[0]`:

   ```json
   {
     "doctor": {"id": 1, "name": "Видлацкая Анна", "specialty": "Офтальмолог"},
     "branch": {
       "id": 2,
       "name": "Север",
       "address": "ул. Московская, 2",
       "city": {"id": 1, "name": "Киров"},
       "clinic": {"id": 1, "name": "Зрение Киров"}
     },
     "starts_at": "2026-11-12T15:00:00+03:00",
     "ends_at": "2026-11-12T15:30:00+03:00",
     "timezone": "Europe/Moscow"
   }
   ```

### К офтальмологу для ребёнка 7 лет в Кирове после 15:00

`POST /api/integrations/v1/availability/search`

```json
{
  "city_id": 1,
  "specialty": "офтальмолог",
  "patient_age": 7,
  "date_from": "2026-11-09",
  "date_to": "2026-11-11",
  "time_from": "15:01"
}
```

Ожидается `200`. У Петровой Ирины, ID `3`, остаются три окна 11 ноября по Москве.

| Начало | Филиал | Адрес |
| --- | --- | --- |
| 16:30 | Север | ул. Московская, 2 |
| 17:00 | Центр | ул. Ленина, 1 |
| 19:00 | Центр | ул. Ленина, 1 |

Контрольные исключения из демо: вчерашнее окно в 16:00, занятое окно Петровой в 16:00, Москва, педиатр, офтальмолог с допуском от 8 лет и время до 15:01.

### Остальные примеры из коллекции

Для фильтров ниже передайте `date_from: "2026-11-11"`, если в строке не указана другая дата.

| Дополнительные поля | Ожидаемый ответ |
| --- | --- |
| `"clinic_ids":[2]` | Только Москва, врачи `2, 5` |
| `"branch_ids":[2]` | Только «Север», врач `3` |
| `"branch_ids":[2,3]` | Только «Север» и «Татьянин парк», врачи `2, 5, 3` в порядке времени |
| `"doctor_ids":[5]` или `"doctor_ids":[2,5]` | Только выбранные врачи |
| `"date_from":"2026-11-12"` | Только 12 ноября, врачи `1, 3, 1` |
| `"time_from":"17:00","time_to":"18:00"` | Одно окно в 17:00 |
| `"patient_age":7` | Врачи `3, 3, 5, 4, 3, 3, 3` по порядку окон |
| Город `1`, клиника `[1]`, филиалы `[1,2]`, врачи `[1,3,4]`, офтальмолог, 7 лет, 15:00–17:00 | Петрова в 15:00, 16:30 и 17:00 |
| `"clinic_ids":[1],"branch_ids":[3]` | `422`, ошибка `branch_ids` |

## Подключение к тестовому контуру

Примените миграции через `php artisan migrate`. Выдайте отдельный секрет вида `client-id.<64 hex-символа>`, используя 32 случайных байта, и передайте его клиенту по закрытому каналу. В конфигурацию Laravel помещается SHA-256 полного секрета. Пример структуры переменной окружения:

```dotenv
BOOKING_INTEGRATION_CLIENTS='{"postman":{"token_hash":"<sha256 полного секрета>","scopes":["catalog:read","availability:read"],"branch_ids":[1,2]}}'
```

Без `branch_ids` ключ действует для всех активных филиалов. Пустой список закрывает доступ ко всем филиалам. Для отзыва удалите запись клиента, для ротации замените хэш. После изменения окружения обновите кэш конфигурации, если он используется. Рабочие ключи и локальные файлы окружения Postman храните за пределами Git.
