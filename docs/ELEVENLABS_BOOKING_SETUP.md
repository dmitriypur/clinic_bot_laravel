# Проверка голосового помощника «Ангелов зрения» в ElevenLabs

## 1. Откройте тестового агента

В **ElevenAgents → Agents** откройте отдельного тестового агента. Через **Tools → Add tool → Webhook** создайте четыре инструмента по настройкам ниже и подключите их к этому агенту.

## 2. Добавьте один Secret для всех четырёх инструментов

1. В `search_catalog` откройте **Headers → Add header**. Введите имя `Authorization`, выберите тип **Secret** и нажмите **Create New Secret**.
2. Назовите секрет `adminzrenie_booking_test`. Вставьте полученную строку целиком, включая `Bearer`. В остальных трёх инструментах добавьте заголовок `Authorization` и выберите тот же Secret.
3. Во все четыре инструмента добавьте заголовок `Accept` со значением `application/json`. В `search_slots` и `create_booking` добавьте также `Content-Type` со значением `application/json`. Для этих заголовков выберите тип **Value**. [Документация ElevenLabs по Secret](https://elevenlabs.io/docs/eleven-agents/customization/tools/webhook-tools#bearer-tokens)

## 3. Заполните параметры инструментов

Для параметров выберите **LLM Prompt**, если редактор предлагает **Value Type**. Если вместо **Integer** редактор предлагает **Number**, выберите **Number**.

### 3.1. `search_catalog` — найти врача, филиал, город или клинику

- **Name** — `search_catalog`
- **Method** — **GET**
- **URL** — `https://test.adminzrenie.ru/api/integrations/v1/catalog/search`
- **Description** — «Ищет врача, филиал, город или клинику по названию, фамилии или адресу. Возвращает совпадения и их номера для поиска свободных окон».

Откройте **Query parameters** и добавьте четыре параметра. Они будут подставляться после адреса автоматически. В поле **URL** оставьте адрес, указанный выше.

- **`type`** · **String** · **Required** включён. **Description** — «Тип поиска. `doctor` — врач, `branch` — филиал, `city` — город, `clinic` — клиника».
- **`q`** · **String** · **Required** включён. **Description** — «Фамилия врача, название или адрес филиала, название города или клиники, как их назвал пациент».
- **`city_id`** · **Integer** · **Required** выключен. **Description** — «Целый номер города из каталога. Передай, если город уже определён и нужен для уточнения поиска».
- **`limit`** · **Integer** · **Required** выключен. **Description** — «Максимальное число совпадений, целое от 1 до 50. Можно пропустить».

Сохраните инструмент.

### 3.2. `search_slots` — найти свободное время

- **Name** — `search_slots`
- **Method** — **POST**
- **URL** — `https://test.adminzrenie.ru/api/integrations/v1/availability/search`
- **Description** — «Ищет свободные окна по врачу, филиалу, городу, специальности, дате, времени и возрасту. Возвращает даты и время свободных окон, а для доступных к записи окон — `offer_token` и `operation_id`».

Откройте **Body parameters** и заполните поля ниже. Если редактор предлагает формат тела запроса, выберите **JSON**. Если над параметрами есть общее поле **Description**, вставьте «Условия поиска свободных окон. Передай только известные фильтры».

- **`doctor_ids`** · **Array** с элементами **Integer** · **Required** выключен. **Description** — «Непустой список целых номеров выбранных врачей из каталога. Если врач не выбран, пропусти поле».
- **`branch_ids`** · **Array** с элементами **Integer** · **Required** выключен. **Description** — «Непустой список целых номеров выбранных филиалов из каталога. Если филиал не выбран, пропусти поле».
- **`clinic_ids`** · **Array** с элементами **Integer** · **Required** выключен. **Description** — «Непустой список целых номеров выбранных клиник из каталога».
- **`city_id`** · **Integer** · **Required** выключен. **Description** — «Целый номер выбранного города из каталога. Если город не задан, пропусти поле».
- **`specialty`** · **String** · **Required** выключен. **Description** — «Название запрошенной специальности, например офтальмолог».
- **`date_from`** · **String** · **Required** включён. **Description** — «Первый день поиска в формате YYYY-MM-DD. Для одного дня передай только это поле даты».
- **`date_to`** · **String** · **Required** выключен. **Description** — «Последний день поиска включительно, в формате YYYY-MM-DD. Передавай только для диапазона. Максимум 31 день вместе с первым и последним днём».
- **`time_from`** · **String** · **Required** выключен. **Description** — «Самое раннее подходящее время начала приёма, в формате HH:mm по местному времени филиала».
- **`time_to`** · **String** · **Required** выключен. **Description** — «Самое позднее подходящее время начала приёма, в формате HH:mm по местному времени филиала».
- **`patient_age`** · **Integer** · **Required** выключен. **Description** — «Возраст пациента в полных годах, целое от 0 до 130. Если возраст неизвестен, пропусти поле».
- **`birth_date`** · **String** · **Required** выключен. **Description** — «Дата рождения YYYY-MM-DD, если уже известна. Передавай только одно из полей `birth_date` и `patient_age`».
- **`limit`** · **Integer** · **Required** включён. **Description** — «Количество окон в ответе. Передай целое число 3».

Для `doctor_ids`, `branch_ids` и `clinic_ids` сначала выберите **Array**. Затем в настройках элементов массива (**Items**) выберите **Integer** или **Number**. Даже один номер передаётся списком, например `[6]`. Если редактор спрашивает описание элемента, введите «Целый номер врача, филиала или клиники из каталога». Сохраните инструмент.

### 3.3. `create_booking` — оформить запись после согласия

- **Name** — `create_booking`
- **Method** — **POST**
- **URL** — `https://test.adminzrenie.ru/api/integrations/v1/bookings`
- **Description** — «Создаёт запись на выбранное окно после явного подтверждения времени и места приёма и согласия пациента на обработку персональных данных для записи».

Добавьте заголовки из шага 2. Откройте **Body parameters**. Если редактор предлагает формат тела запроса, выберите **JSON**. Если есть общее поле **Description**, вставьте «Данные пациента и выбранного окна после подтверждения записи и согласия на обработку данных».

- **`offer_token`** · **String** · **Required** включён. **Description** — «Скопируй целиком точное значение поля offer_token из выбранного окна в ответе search_slots. Используй именно поле offer_token окна».
- **`full_name`** · **String** · **Required** включён. **Description** — «Фамилия и имя пациента, а также отчество, если оно есть. Передай подтверждённое написание».
- **`birth_date`** · **String** · **Required** включён. **Description** — «Дата рождения пациента в формате YYYY-MM-DD».
- **`phone`** · **String** · **Required** включён. **Description** — «Телефон в формате +7 и десять цифр без пробелов».
- **`full_name_parent`** · **String** · **Required** выключен. **Description** — «ФИО родителя или представителя, если сообщили».
- **`confirmed`** · **Boolean** · **Required** включён. **Description** — «Передай true только после явного подтверждения выбранного врача, адреса, даты и времени приёма».
- **`privacy_consent`** · **Boolean** · **Required** включён. **Description** — «Передай true только после явного согласия на обработку персональных данных для записи».
- **`comment`** · **String** · **Required** выключен. **Description** — «Только для согласованной тестовой записи передай комментарий „ТЕСТ. Не связываться.“. В обычной записи пропусти поле».

У обоих подтверждений должен стоять **Value Type → LLM Prompt**. Значение `true` агент отправляет по итогам разговора. Заголовок `Idempotency-Key` оставьте незаданным. Сервер берёт номер попытки из `offer_token`. Сохраните инструмент.

### 3.4. `get_booking_status` — проверить результат той же попытки

- **Name** — `get_booking_status`
- **Method** — **GET**
- **URL** — `https://test.adminzrenie.ru/api/integrations/v1/operations/{operation_id}`
- **Description** — «Проверяет результат уже отправленной попытки записи по номеру операции».

Добавьте заголовки из шага 2. Оставьте `{operation_id}` в конце URL вместе с фигурными скобками. После вставки адреса откройте **Path parameters**. Выберите появившееся поле `operation_id`. Если редактор предлагает добавить его вручную, нажмите **Add parameter**.

- **`operation_id`** · **String** · **Required** включён, если есть переключатель. **Value Type → LLM Prompt**. **Description** — «Точный номер операции (UUID) выбранного окна из search_slots или из ответа create_booking. Используй номер той же попытки записи».

Сохраните инструмент. Вернитесь к **Tools** тестового агента и проверьте, что в списке есть все четыре инструмента. Откройте каждый и проверьте строку `Authorization`.

## 4. Вставьте промпт

Откройте **Agent → System prompt** тестового агента. Установите **Europe/Moscow** через кнопку часового пояса в редакторе. Вставьте блок записи в промпт и сохраните настройки тестового агента. [Настройка часового пояса](https://elevenlabs.io/docs/eleven-agents/customization/personalization/dynamic-variables#time-and-timezone)

```text
Запись на приём через тестовый агент «Ангелов зрения»

Отвечай кратко и по-русски. В Preview принимай только вымышленные данные. Вопросы о лечении, цене, переносе и отмене обрабатывай по действующим правилам агента. Если в них нет ответа, предложи обратиться в регистратуру.

Поиск
- Используй все названные условия. Если назван только адрес, ищи подходящих врачей в этом филиале. Если назван только врач, ищи его во всех доступных филиалах. Если пользователь изменил одно условие, сохрани остальные.
- Для поиска врача, филиала, города или клиники вызови search_catalog с type=doctor, branch, city или clinic. В q передай фамилию, название или адрес как услышал. Если есть несколько подходящих вариантов, meta.ambiguous=true или meta.approximate=true, коротко уточни выбор перед поиском окон. Уже подтверждённый выбор повторно не уточняй. Используй номера из каталога.
- Для дат используй текущую дату в часовом поясе агента. Переводи «завтра» и «послезавтра» в точную дату. Для «на 22-е» выбери ближайшее предстоящее 22-е с учётом контекста. При неоднозначности уточни дату.
- Вызови search_slots. Для одного дня передай только date_from, для диапазона добавь date_to. Формат дат YYYY-MM-DD. Для «на ближайшее время» и поиска без даты начни с 7 дней, включая сегодня. Если подходящих окон нет, проверь следующие дни в пределах ближайшего месяца с теми же условиями. Один запрос охватывает максимум 31 день.
- Передавай только известные фильтры. Для doctor_ids, branch_ids и clinic_ids используй непустые списки целых чисел. Учитывай город, специальность, время и возраст, если они указаны. Передавай limit=3.
- Предложи до трёх ближайших окон. Назови дату и время приёма. Если варианты различаются по врачу или филиалу, назови врача или адрес, чтобы пациент мог выбрать.
- При meta.schedule_status=complete и meta.empty_reason=no_schedule скажи, что по заданным условиям приёма в эти даты нет. При complete и no_available_slots либо пустой полной выдаче без причины скажи, что подходящих свободных окон нет. При partial скажи, что проверена только часть расписания, и предложи найденные окна. При schedule_unavailable или ошибке скажи, что расписание проверить не удалось. Если подходящих окон нет, предложи другой день.

Запись
- Используй только выбранное окно с offer_token. Сохрани из одного и того же окна точные offer_token и operation_id. Если offer_token отсутствует, скажи, что это окно недоступно для записи через помощника, и предложи другое.
- Спроси ФИО пациента, дату рождения и телефон. Для ребёнка уточни ФИО родителя или представителя. Если фамилия неясна или пациент её поправил, попроси произнести её по буквам, повтори исправленное написание и дождись подтверждения.
- Коротко назови ФИО пациента, врача, дату, время и адрес. Попроси подтвердить запись на это окно и дать согласие на обработку персональных данных для записи. Если подтверждено только одно, спроси про второе. При отказе или отсутствии любого подтверждения не вызывай create_booking.
- После обоих явных подтверждений вызови create_booking один раз. Передай confirmed=true, privacy_consent=true и точный offer_token выбранного окна. Для согласованной тестовой записи передай comment «ТЕСТ. Не связываться.».
- Скажи «Вы записаны» только при status=confirmed. Если пользователь просит проверить только что созданную запись, вызови get_booking_status с operation_id из create_booking. При code=slot_unavailable обнови поиск и предложи другое время. При code=offer_expired заново найди то же окно и, если оно доступно, попроси подтвердить его перед записью с новым offer_token. При другом явном отказе скажи, что запись не создалась.
- При status=unknown, таймауте, потере ответа или ошибке инструмента без ясного исхода вызови get_booking_status. Передай operation_id той же попытки из ответа create_booking или из исходного выбранного окна, если ответ потерян. При confirmed подтверди запись. При явном отказе сообщи об отказе. Если исход остаётся неизвестным, скажи «Запись пока не подтверждена. Уточните её в регистратуре». Не отправляй повторную запись.
- Опирайся на ответы инструментов. Служебные номера и токены пациенту не произноси.
```

## 5. Проверьте запись в Preview

1. В **Preview → New conversation** разрешите доступ к микрофону и скажите «Найдите ближайшее время для взрослого на Преображенской, 38, в Кирове». Выберите предложенное окно.
2. Сообщите вымышленные данные. «Фамилия Примеров, имя Василий, дата рождения первое января 1990 года, телефон плюс семь и десять нулей. Комментарий — “ТЕСТ. Не связываться.”».
3. Дождитесь, пока агент повторит врача, дату, время и адрес. Скажите «Подтверждаю запись на это время. Даю согласие на обработку персональных данных для записи». После подтверждения записи скажите «Проверьте статус этой записи».
4. В **View details** проверьте, что `search_catalog` нашёл филиал, `search_slots` вернул выбранное окно с токеном, `create_booking` вызван один раз с обоими согласиями, а `get_booking_status` вернул `confirmed` для того же `operation_id` и `booking_id`.
5. В новом разговоре повторите поиск для Москвы, например по филиалу «Татьянин парк». Проверьте предложенное время в `search_slots`. [Проверка агента в ElevenLabs](https://elevenlabs.io/docs/eleven-agents/quickstart#testing-your-assistant)
