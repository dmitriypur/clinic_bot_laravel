# Подключение записи «Ангелов зрения» к действующему агенту ElevenLabs

После настройки ваш агент сможет искать врачей и филиалы, предлагать свободное время и оформлять запись через adminzrenie.ru. Все шаги выполняются в браузере в настройках вашего рабочего агента.

## 1. Получите действующий ключ adminzrenie.ru

1. Получите у сотрудника, который передал вам эту инструкцию, **полный действующий ключ adminzrenie.ru**. Он начинается с `elevenlabs.`. Для подключения используется уже выданный ключ. Попросите также список филиалов, доступных по этому ключу.
2. Получите ключ лично или через принятый в компании способ защищённой передачи паролей. Введите его в защищённое поле **Secret** в своём рабочем пространстве ElevenLabs на шаге 3.
3. Войдите в рабочее пространство клиники в ElevenLabs. У вашей учётной записи должны быть права на редактирование этого агента, добавление инструментов и создание секретов. Для голосовой проверки понадобятся доступные минуты или кредиты.

Для всех четырёх инструментов у ключа должны быть права `catalog:read`, `availability:read`, `bookings:write` и `operations:read`. Если какой-либо инструмент возвращает ошибку доступа, попросите администратора adminzrenie.ru проверить права клиента `elevenlabs` и разрешённые филиалы.

## 2. Откройте рабочего агента и редактор инструментов

1. В ElevenLabs откройте **ElevenAgents → Agents** и выберите агента, который уже отвечает пациентам. Сверьте его имя.
2. Откройте **Tools → Add tool**. В окне добавления выберите **Webhook** в поле **Tool Type**. Если сначала открылся список готовых инструментов, выберите создание инструмента, затем **Webhook**.
3. Начните с `search_catalog`. Возьмите **Name**, **Description**, **Method** и **URL** из пункта 4.1, добавьте заголовки по шагу 3 и параметры из пункта 4.1. Затем заполните остальные инструменты по пунктам 4.2–4.4. Если после сохранения открывается список инструментов, выберите только что сохранённый инструмент, чтобы прикрепить его к агенту.
4. Если в рабочем пространстве уже есть одноимённый инструмент тестового агента, создайте отдельный инструмент для рабочего агента. Настройки общего инструмента применяются ко всем агентам, которые его используют. В списке инструментов рабочего агента должно быть по одному инструменту с каждым из четырёх имён. [Инструменты Webhook](https://elevenlabs.io/docs/eleven-agents/customization/tools/webhook-tools) · [Как ElevenLabs применяет изменения общих инструментов](https://elevenlabs.io/docs/eleven-agents/customization/tools/tool-configuration/editing-tools)

## 3. Создайте один Secret и добавьте заголовки

Начните с инструмента `search_catalog`. В его редакторе выполните следующие действия.

1. Откройте **Headers** (или **Request Headers**) → **Add header**. В поле имени заголовка введите `Authorization`. В поле **Type** выберите **Secret**, затем **Create New Secret**.
2. В окне создания секрета введите имя `adminzrenie_booking`. В поле значения напишите `Bearer`, поставьте один пробел и сразу после него вставьте полученный ключ. Если администратор уже прислал значение с префиксом `Bearer`, вставьте его целиком один раз. Сохраните секрет и убедитесь, что `adminzrenie_booking` выбран в строке `Authorization`.
3. В остальных трёх инструментах также откройте **Headers → Add header**, введите имя `Authorization`, установите **Type → Secret** и выберите из списка уже сохранённый `adminzrenie_booking`. Один и тот же секрет должен быть выбран **во всех четырёх** инструментах. Храните значение ключа в Secret.
4. В каждом инструменте через **Add header** добавьте `Accept`, тип **Value**, значение `application/json`.
5. В двух инструментах с методом **POST**, `search_slots` и `create_booking`, добавьте ещё один заголовок `Content-Type`, тип **Value**, значение `application/json`. [Настройка Bearer-авторизации в ElevenLabs](https://elevenlabs.io/docs/eleven-agents/customization/tools/webhook-tools#bearer-tokens)

## 4. Заполните четыре инструмента

В нужном разделе нажимайте **Add parameter** для каждого поля из списка. Скопируйте имя в **Identifier**, выберите указанный **Data Type**, установите **Required** и вставьте текст из **Description**. Во всех параметрах, где редактор предлагает **Value Type**, выбирайте **LLM Prompt**. Так агент сам заполнит поле из разговора или из результата предыдущего вызова. Значения из примеров в описаниях служат подсказками для агента.

Для целых чисел ниже используйте **Integer**. Если в вашем редакторе этот тип называется **Number**, выберите **Number**. В описаниях уже указано, где значение должно быть целым.

### 4.1. `search_catalog` — найти врача, филиал, город или клинику

- **Name** — `search_catalog`
- **Method** — **GET**
- **URL** — `https://adminzrenie.ru/api/integrations/v1/catalog/search`
- **Description** — «Ищет врача, филиал, город или клинику по названию, фамилии или адресу. Возвращает совпадения и их номера для поиска свободных окон».

Добавьте заголовки из шага 3. Откройте **Query parameters** и добавьте четыре параметра. Они будут подставляться после адреса автоматически. В поле **URL** оставьте адрес, указанный выше.

- **`type`** · **String** · **Required** включён. **Description** — «Тип поиска. `doctor` — врач, `branch` — филиал, `city` — город, `clinic` — клиника».
- **`q`** · **String** · **Required** включён. **Description** — «Фамилия врача, название или адрес филиала, название города или клиники, как их назвал пациент».
- **`city_id`** · **Integer** · **Required** выключен. **Description** — «Целый номер города из каталога. Передай, если город уже определён и нужен для уточнения поиска».
- **`limit`** · **Integer** · **Required** выключен. **Description** — «Максимальное число совпадений, целое от 1 до 50. Можно пропустить».

Сохраните инструмент.

### 4.2. `search_slots` — найти свободное время

- **Name** — `search_slots`
- **Method** — **POST**
- **URL** — `https://adminzrenie.ru/api/integrations/v1/availability/search`
- **Description** — «Ищет свободные окна по врачу, филиалу, городу, специальности, дате, времени и возрасту. Возвращает время и данные выбранного окна для записи».

Добавьте заголовки из шага 3. Откройте **Body parameters** и заполните поля ниже. Если редактор предлагает формат тела запроса, выберите **JSON**. Если над параметрами есть общее поле **Description**, вставьте «Условия поиска свободных окон. Передай только известные фильтры».

- **`doctor_ids`** · **Array** с элементами **Integer** · **Required** выключен. **Description** — «Непустой список целых номеров выбранных врачей из каталога. Если врач не выбран, пропусти поле».
- **`branch_ids`** · **Array** с элементами **Integer** · **Required** выключен. **Description** — «Непустой список целых номеров выбранных филиалов из каталога. Если филиал не выбран, пропусти поле».
- **`city_id`** · **Integer** · **Required** выключен. **Description** — «Целый номер выбранного города из каталога. Если город не задан, пропусти поле».
- **`specialty`** · **String** · **Required** выключен. **Description** — «Название запрошенной специальности, например офтальмолог».
- **`date_from`** · **String** · **Required** включён. **Description** — «Первый день поиска в формате YYYY-MM-DD. Для одного дня передай только это поле даты».
- **`date_to`** · **String** · **Required** выключен. **Description** — «Последний день поиска включительно, в формате YYYY-MM-DD. Передавай только для диапазона. Максимум 31 день вместе с первым и последним днём».
- **`time_from`** · **String** · **Required** выключен. **Description** — «Самое раннее подходящее время начала приёма, в формате HH:mm по местному времени филиала».
- **`time_to`** · **String** · **Required** выключен. **Description** — «Самое позднее подходящее время начала приёма, в формате HH:mm по местному времени филиала».
- **`patient_age`** · **Integer** · **Required** выключен. **Description** — «Возраст пациента в полных годах, целое от 0 до 130. Если возраст неизвестен, пропусти поле».
- **`limit`** · **Integer** · **Required** включён. **Description** — «Количество окон в ответе. Передай целое число 3».

Для `doctor_ids` и `branch_ids` сначала выберите **Array**. Затем в настройках элементов массива (**Items**) выберите **Integer** или **Number**. Даже один номер передаётся списком, например `[6]`. Если редактор спрашивает описание элемента, введите «Целый номер врача из каталога» или «Целый номер филиала из каталога». Сохраните инструмент.

### 4.3. `create_booking` — оформить запись после согласия

- **Name** — `create_booking`
- **Method** — **POST**
- **URL** — `https://adminzrenie.ru/api/integrations/v1/bookings`
- **Description** — «Создаёт запись на выбранное окно после явного подтверждения времени и места приёма и согласия пациента на обработку персональных данных для записи».

Добавьте заголовки из шага 3. Откройте **Body parameters**. Если редактор предлагает формат тела запроса, выберите **JSON**. Если есть общее поле **Description**, вставьте «Данные пациента и выбранного окна после подтверждения записи и согласия на обработку данных».

- **`offer_token`** · **String** · **Required** включён. **Description** — «Скопируй целиком точное значение поля offer_token из выбранного окна в ответе search_slots. Поле id вида onec:… для записи не подходит».
- **`full_name`** · **String** · **Required** включён. **Description** — «Фамилия и имя пациента, а также отчество, если оно есть. Передай подтверждённое написание».
- **`birth_date`** · **String** · **Required** включён. **Description** — «Дата рождения пациента в формате YYYY-MM-DD».
- **`phone`** · **String** · **Required** включён. **Description** — «Телефон в формате +7 и десять цифр без пробелов».
- **`full_name_parent`** · **String** · **Required** выключен. **Description** — «ФИО родителя или представителя, если сообщили».
- **`confirmed`** · **Boolean** · **Required** включён. **Description** — «Передай true только после явного подтверждения выбранного врача, адреса, даты и времени приёма».
- **`privacy_consent`** · **Boolean** · **Required** включён. **Description** — «Передай true только после явного согласия на обработку персональных данных для записи».
- **`comment`** · **String** · **Required** выключен. **Description** — «Только для согласованной тестовой записи передай комментарий „ТЕСТ. Не связываться.“. В обычной записи пропусти поле».

У обоих подтверждений должен стоять **Value Type → LLM Prompt**. Значение `true` агент отправляет по итогам разговора. Заголовок `Idempotency-Key` оставьте незаданным. Сервер берёт номер попытки из `offer_token`. Сохраните инструмент.

### 4.4. `get_booking_status` — проверить результат той же попытки

- **Name** — `get_booking_status`
- **Method** — **GET**
- **URL** — `https://adminzrenie.ru/api/integrations/v1/operations/{operation_id}`
- **Description** — «Проверяет результат уже отправленной попытки записи после неизвестного ответа, таймаута или потери ответа».

Добавьте заголовки из шага 3. Оставьте `{operation_id}` в конце URL вместе с фигурными скобками. После вставки адреса откройте **Path parameters**. Выберите появившееся поле `operation_id`. Если редактор предлагает добавить его вручную, нажмите **Add parameter**.

- **`operation_id`** · **String** · **Required** включён, если есть переключатель. **Value Type → LLM Prompt**. **Description** — «Точный номер операции (UUID) выбранного окна из search_slots или из ответа create_booking. Используй номер той же попытки записи».

Сохраните инструмент. Вернитесь к **Tools** рабочего агента и проверьте, что в списке есть все четыре инструмента. Откройте каждый и проверьте строку `Authorization`.

## 5. Дополните существующий System prompt

1. Откройте **Agent → System prompt**. Сохраните копию текущего текста у себя. Скопируйте блок ниже в конец действующего промпта, начиная с заголовка «Запись на приём через adminzrenie.ru».
2. Сохраните действующие правила общения, ответы на общие вопросы и порядок перевода на сотрудника. Если в тексте уже есть инструкции про поиск времени и запись, согласуйте этот фрагмент с новым блоком, чтобы у агента был один порядок действий.
3. В редакторе **System prompt** нажмите кнопку часового пояса и проверьте **Europe/Moscow** для поиска по текущему пилоту. С этим параметром ElevenLabs передаёт агенту текущую дату и время для понимания фраз «завтра» и «послезавтра». [Настройка времени в ElevenLabs](https://elevenlabs.io/docs/eleven-agents/customization/personalization/dynamic-variables#time-and-timezone)

```text
Запись на приём через adminzrenie.ru

В сценарии записи отвечай кратко и по-русски. Вопросы о лечении, цене, переносе и отмене обрабатывай по действующим правилам агента. Если в них нет ответа, предложи обратиться в регистратуру.

Поиск
- Используй все названные условия. Если назван только адрес, ищи подходящих врачей в этом филиале. Если назван только врач, ищи его во всех доступных филиалах. Если пользователь изменил одно условие, сохрани остальные.
- Для поиска врача, филиала, города или клиники вызови search_catalog с type=doctor, branch, city или clinic. В q передай фамилию, название или адрес как услышал. Если есть несколько подходящих вариантов, meta.ambiguous=true или meta.approximate=true, коротко уточни выбор перед поиском окон. Уже подтверждённый выбор повторно не уточняй. Используй номера из каталога.
- Для дат используй текущую дату в часовом поясе агента. Переводи «завтра» и «послезавтра» в точную дату. Для «на 22-е» выбери ближайшее предстоящее 22-е с учётом контекста. При неоднозначности уточни дату.
- Вызови search_slots. Для одного дня передай только date_from, для диапазона добавь date_to. Формат дат YYYY-MM-DD. Для «на ближайшее время» и поиска без даты начни с 7 дней, включая сегодня. Если подходящих окон нет, проверь следующие дни в пределах ближайшего месяца с теми же условиями. Один запрос охватывает максимум 31 день.
- Передавай только известные фильтры. Для doctor_ids и branch_ids используй непустые списки целых чисел. Учитывай город, специальность, время и возраст, если они указаны. Передавай limit=3.
- Предложи до трёх ближайших окон. Назови дату и время приёма. Если варианты различаются по врачу или филиалу, назови врача или адрес, чтобы пациент мог выбрать.
- При meta.schedule_status=complete и meta.empty_reason=no_schedule скажи, что по заданным условиям приёма в эти даты нет. При complete и no_available_slots либо пустой полной выдаче без причины скажи, что подходящих свободных окон нет. При partial скажи, что проверена только часть расписания, и предложи найденные окна. При schedule_unavailable или ошибке скажи, что расписание проверить не удалось. Если подходящих окон нет, предложи другой день.

Запись
- Используй только выбранное окно с offer_token. Сохрани из одного и того же окна точные offer_token и operation_id. Если offer_token отсутствует, скажи, что это окно недоступно для записи через помощника, и предложи другое. Значение id вида onec:… для записи не подходит.
- Спроси ФИО пациента, дату рождения и телефон. Для ребёнка уточни ФИО родителя или представителя. Если фамилия неясна или пациент её поправил, попроси произнести её по буквам, повтори исправленное написание и дождись подтверждения.
- Коротко назови ФИО пациента, врача, дату, время и адрес. Попроси подтвердить запись на это окно и дать согласие на обработку персональных данных для записи. Если подтверждено только одно, спроси про второе. При отказе или отсутствии любого подтверждения не вызывай create_booking.
- После обоих явных подтверждений вызови create_booking один раз. Передай confirmed=true, privacy_consent=true и точный offer_token выбранного окна. Для согласованной тестовой записи передай comment «ТЕСТ. Не связываться.».
- Скажи «Вы записаны» только при status=confirmed. При code=slot_unavailable обнови поиск и предложи другое время. При code=offer_expired заново найди то же окно и, если оно доступно, попроси подтвердить его перед записью с новым offer_token. При другом явном отказе скажи, что запись не создалась.
- При status=unknown, таймауте, потере ответа или ошибке инструмента без ясного исхода вызови get_booking_status. Передай operation_id той же попытки из ответа create_booking или из исходного выбранного окна, если ответ потерян. При confirmed подтверди запись. При явном отказе сообщи об отказе. Если исход остаётся неизвестным, скажи «Запись пока не подтверждена. Уточните её в регистратуре». Не отправляй повторную запись.
- Опирайся на ответы инструментов. Служебные номера и токены пациенту не произноси.
```

## 6. Сохраните настройки и проверьте поиск

1. Откройте **Preview** и проверьте, какую версию агента он запускает. Если доступны текущие правки, начните проверку там. Если Preview запускает опубликованную конфигурацию, сохраните изменения кнопкой **Save** или **Publish**. Если появится **Review Changes**, проверьте добавленные инструменты и изменения **System prompt** и подтвердите публикацию. Публикация на ветке **Main**, обслуживающей звонки, может сразу включить новый сценарий для пациентов. Согласуйте момент публикации с клиникой. Если у агента уже есть ветка для проверки, можно сначала сохранить правки и проверить их там. [Версии агента и публикация](https://elevenlabs.io/docs/eleven-agents/operate/versioning)
2. Выберите **Preview → New conversation** или **Test AI agent** и разрешите браузеру доступ к микрофону. Начинайте каждый пример в новом разговоре. Для проверки поиска достаточно дождаться предложенных вариантов и завершить разговор.
3. Откройте **View details** у вызова инструмента. Если закрыли разговор, найдите его в **Call history**. В деталях посмотрите, что отправил агент и что вернул сервер. [Проверка агента и история разговоров](https://elevenlabs.io/docs/eleven-agents/quickstart#testing-your-assistant)

- **По адресу.** Скажите «Какие врачи свободны завтра на Преображенской, 38?». Проверьте, что `search_catalog` получил `type=branch`, а `search_slots` — список с номером найденного филиала и завтрашнюю дату в `date_from`. Поле `doctor_ids` должно отсутствовать.
- **По врачу.** Скажите «Найдите ближайшее время у врача» и назовите фамилию из каталога клиники. При нескольких совпадениях агент должен уточнить выбор. В `search_slots` должны попасть номер врача в `doctor_ids` и период в семь дней, включая сегодня. Если нет окон, проверьте, что при расширении периода сохранился выбранный врач.
- **По дате и времени.** В отдельных разговорах попросите найти время «послезавтра после 15:00» и «на 22-е». Сверьте точную дату в `date_from` и `time_from=15:00` в первом случае.
- **По специальности и возрасту.** Скажите «Найдите офтальмолога для ребёнка семи лет». Проверьте, что `search_slots` получил специальность и `patient_age=7`.

Если нашлось окно для записи, у него в ответе `search_slots` должны быть `offer_token` и `operation_id`. Успешный поиск может вернуть пустой список, если по этим условиям нет подходящего времени. Для проверки наличия токена возьмите другой день или филиал из списка администратора.

## 7. Проведите одну согласованную тестовую запись

**Тест создаёт реальную запись в 1С.** Заранее согласуйте с администратором филиал, тестовое окно, данные для проверки и сотрудника, который сможет сразу проверить и отменить запись. Для теста используйте только данные, полученные по закрытому каналу специально для этой проверки.

1. В **Preview → New conversation** попросите найти согласованное окно. При необходимости сначала проверьте отказ от согласия отдельным разговором. После выбора окна и запроса подтверждения скажите «Время подтверждаю, согласия на обработку данных не даю». В деталях разговора убедитесь, что вызова `create_booking` нет.
2. Для согласованной записи начните новый разговор и заново найдите окно. Предложение из `search_slots` действует 10 минут. Выберите окно голосом, сообщите согласованные тестовые данные и попросите добавить комментарий «ТЕСТ. Не связываться.».
3. Дождитесь, пока агент назовёт пациента, врача, дату, время и адрес. Подтвердите выбранное окно и явно дайте согласие на обработку данных для тестовой записи.
4. В **View details** проверьте один вызов `create_booking`. В нём должны быть точный `offer_token` из выбранного окна, оба значения `true` и тестовый комментарий. Ожидаемый ответ — `status=confirmed`. Попросите администратора проверить в админке и 1С, что запись и комментарий соответствуют договорённости. Затем отмените тестовую запись через администратора и проверьте отмену в 1С.
5. Если ответ потерян, истекло время ожидания или пришёл `status=unknown`, убедитесь, что агент вызвал `get_booking_status` с `operation_id` той же попытки. Если статус по-прежнему неизвестен, передайте администратору номер операции, филиал, врача и время для сверки с 1С. Дождитесь сверки перед любой новой попыткой на это окно.

В пилоте запись через Postman и тестового голосового агента успешно прошла на Эйзенштейна, 6. Эти тестовые записи удалены. Во всех восьми филиалах пилота поиск вернул окна с токенами записи. Расширенную голосовую проверку после обновления промпта прервал лимит ElevenLabs. Выполните проверки выше в своём рабочем агенте с полученным ключом.

Перед запуском записи для пациентов согласуйте с клиникой формулировку согласия, доступ к истории разговоров и срок хранения записей и расшифровок. Если проверяли изменения на отдельной ветке, после проверки перенесите их в рабочую ветку через меню управления ветками и проверьте опубликованный список инструментов. ## Если проверка не проходит

- **`quota_exceeded`.** Проверьте остаток минут или кредитов в рабочем пространстве ElevenLabs. Когда лимит снова станет доступен, начните новый разговор.
- **`401`.** В инструменте, который вернул ошибку, проверьте `Authorization`, тип **Secret** и выбранный `adminzrenie_booking`. Значение секрета должно начинаться с `Bearer` и одного пробела.
- **`403`.** Попросите администратора adminzrenie.ru проверить права ключа рабочего агента.
- **`422`.** Откройте детали вызова и посмотрите, какое поле указано в ошибке. Проверьте обязательные поля, форматы дат и времени и списки целых чисел. Неизвестные необязательные фильтры должны отсутствовать.
- **У окна нет `offer_token`.** Сверьте выбранный Secret в `search_slots` и `create_booking`. Попросите администратора проверить, что запись открыта для этого филиала и ключа.
- **В `create_booking` попало значение вида `onec:…`.** Сверьте описание `offer_token` и блок промпта. Агент должен передавать точное значение поля `offer_token` из выбранного окна.
