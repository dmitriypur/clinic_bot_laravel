# Контактные данные в уведомлении об ошибке записи

## Цель

Если сайт не смог передать запись клиента в 1С, сотрудник должен получить в настроенном чате Bitrix24 достаточно данных, чтобы сразу позвонить клиенту или оформить запись вручную.

## Поведение

- В существующее уведомление `ОШИБКА ЗАПИСИ КЛИЕНТА` добавить две строки: `Клиент` и `Телефон`.
- Значения брать из уже проверенных полей запроса `full_name` и `phone`.
- ФИО родителя, дата рождения и остальные персональные данные в сообщение не добавляются.
- Существующая подробная классификация технической ошибки сохраняется без изменений.
- Сообщение клиенту на сайте и HTTP-код 503 остаются без изменений.
- Неудачная заявка, как и сейчас, не сохраняется в админке.
- Уведомление отправляется только при технической ошибке передачи записи в 1С; ошибки правил записи по-прежнему возвращаются клиенту без такого уведомления.

## Безопасность

- В Bitrix24 допускаются только явно перечисленные ФИО пациента и телефон.
- URL 1С, токены, тело ответа, исходный текст исключения и прочие поля контекста по-прежнему игнорируются фабрикой сообщения.
- Доступ к групповому чату Bitrix24 должен быть только у сотрудников, которым разрешено работать с заявками клиентов.

## Проверка

- Модульный тест подтверждает наличие ФИО и телефона и отсутствие секретных технических данных.
- Сквозные API-тесты подтверждают наличие контактов как при недоступности предварительной проверки, так и при ошибке реальной передачи в 1С.
- API по-прежнему возвращает клиенту прежнее понятное сообщение, а запись не остаётся в базе.
