# Понятные причины ошибок записи в 1С

## Цель

Заменить общее сообщение «Техническая ошибка соединения с 1С» в уведомлениях Bitrix24 на конкретное и понятное описание фактической технической причины, чтобы сотрудник сразу понимал, куда обращаться: к специалистам 1С, к хостингу или к разработчику сайта.

## Границы задачи

- Меняется только описание технической ошибки в уведомлении Bitrix24 и серверном журнале.
- Клиент продолжает получать прежнее безопасное сообщение: «Онлайн-запись временно недоступна. Попробуйте позже или свяжитесь с клиникой по телефону».
- Неудавшиеся заявки по-прежнему не сохраняются.
- Автоматические повторные записи не добавляются, чтобы не создавать дубли в 1С.
- Плановые и ручные HEAD-проверки доступности не изменяются.
- Виджет «Зрение Клиник» не изменяется.

## Классификация причин

При неудачной реальной записи клиента уведомление должно содержать этап «Передача записи клиента в 1С» и одну из следующих причин:

- `HTTP 500–599`: «Сервер 1С или промежуточный сервер вернул HTTP N».
- `HTTP 401/403`: «1С отклонила авторизацию, HTTP N».
- `HTTP 408`: «Сервер 1С сообщил о тайм-ауте, HTTP 408».
- `HTTP 429`: «1С временно ограничила количество запросов, HTTP 429».
- Тайм-аут клиента Laravel/cURL: «1С не ответила за N секунд»; если точное время недоступно — «Истекло время ожидания ответа от 1С».
- Отказ в соединении: «Соединение с сервером 1С отклонено».
- Ошибка DNS: «Не удалось определить адрес сервера 1С».
- TLS/SSL: «Ошибка защищённого соединения с сервером 1С».
- Разрыв или пустой ответ: «Соединение с 1С было прервано до получения ответа».
- Некорректный формат ответа: «1С ответила, но вернула некорректные данные».
- Остальные сетевые ошибки: «Сетевая ошибка между сервером сайта и 1С».
- Техническая ошибка без доступных деталей: «Не удалось получить подтверждение записи от 1С».

Формулировки описывают наблюдаемый факт и не утверждают без доказательств, что виновата исключительно 1С. Например, HTTP 502 может вернуть сама публикация 1С или прокси перед ней.

## Передача технического контекста

`OneCApiClient` уже получает исходное исключение HTTP-клиента, но сейчас не сохраняет безопасные признаки ошибки в контексте `OneCApiException`. В контекст добавляются только:

- категория ошибки (`timeout`, `connection_refused`, `dns`, `tls`, `connection_reset`, `network`, `invalid_response`);
- числовой cURL-код, если он доступен;
- настроенное время ожидания в секундах;
- HTTP-статус ответа, если сервер ответил.

Полный текст исключения остаётся в защищённом Laravel log для диагностики, но не отправляется в Bitrix24.

## Безопасность сообщений

В Bitrix24 запрещено передавать:

- URL конкретного обработчика записи;
- заголовки авторизации, логины, пароли и токены;
- тело запроса или ответа 1С;
- ФИО, телефон и дату рождения клиента;
- исходный текст системного исключения целиком.

Сохраняются уже используемые безопасные сведения: филиал, врач, желаемое время и внутренний номер неудачной попытки.

## Поток обработки

1. Виджет отправляет заявку в Laravel.
2. Laravel успешно проходит предварительную HEAD-проверку и вызывает обработчик создания записи 1С.
3. При ошибке `OneCApiClient` определяет безопасную категорию и записывает подробность в контекст исключения.
4. `OneCBookingService` переносит контекст в `OneCBookingException` без потери категории.
5. `OneCBookingFailureClassifier` формирует понятную русскую причину.
6. Bitrix24 получает уведомление с этапом и конкретной причиной.
7. Клиент получает прежнее понятное сообщение без технических подробностей.

## Журналирование

В Laravel log сохраняются endpoint ID, HTTP-статус или категория сетевой ошибки, cURL-код и исходное системное сообщение. Это позволяет разработчику проводить точную диагностику, если одной формулировки Bitrix24 недостаточно.

Персональные данные и секреты не должны добавляться в новые записи журнала. Существующее журналирование тела запроса/ответа не расширяется в рамках этой задачи.

## Проверки

- HTTP 502 превращается в понятное сообщение о сервере 1С или промежуточном сервере.
- HTTP 401 и 403 описываются как ошибка авторизации.
- HTTP 408 и 429 имеют отдельные формулировки.
- Тайм-аут, отказ соединения, DNS, TLS и разрыв соединения классифицируются отдельно.
- Некорректный ответ 1С имеет отдельную причину.
- Неизвестная техническая ошибка получает нейтральную запасную формулировку.
- В сообщениях Bitrix24 отсутствуют секреты, тело ответа и персональные данные клиента.
- Существующий HTTP 503 для виджета и удаление неудачной заявки сохраняются.
- Плановые и ручные проверки продолжают работать без изменений.
